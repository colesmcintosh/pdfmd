pdf → md

A fast, zero-dependency PDF → Markdown converter written in Rust. pdfmd parses the object graph, inflates the compressed streams, decodes the fonts, and interprets the content-stream operators itself — then recovers headings, lists, and paragraphs with a small set of heuristics.

Why

PDFs carry no semantic structure

Most extraction libraries either hand back one undifferentiated text blob, or stop at a slow, general-purpose parsing layer. pdfmd owns the whole path from bytes to Markdown — which is what keeps it fast, and what leaves room to tune the heuristics for the documents you actually care about.

Zero dependencies

The CLI parser, error type, work scheduler, PDF reader, and zlib/DEFLATE decoder all live in this crate. Nothing to audit but the crate itself.

~240 MB/s of PDF

About 3,900 pages/sec. Pages extract in parallel over a std::thread::scope pool, and fonts shared across pages are parsed once into a document-wide cache.

Structure, not a blob

Headings, list items, and paragraph boundaries are recovered from font sizes, line spacing, and leading glyphs — and the first paragraph is promoted to an H1 title.

Real font decoding

ToUnicode CMaps (bfchar/bfrange), WinAnsi / MacRoman / Standard / Symbol encodings, /Differences arrays, and glyph-name → Unicode fallback.

Image extraction

JPEG and JPEG 2000 streams pass through verbatim; decoded 8-bit gray/RGB/CMYK rasters are re-encoded to PNG and linked inline at their paint position.

Tested to 100%

391 tests (364 unit, 27 integration) at 100% line coverage and 99.77% region coverage, gated on Linux, macOS, and Windows with -D warnings.

Architecture

Bytes in, Markdown out — every layer in one crate

│   ├── image.rs          image XObjects → assets

│   └── mod.rs            page walking + parallelism
├── heuristics.rs         headings, lists, reflow
├── lib.rs                public API
├── cli.rs                argv parsing + execution
└── main.rs               process entrypoint
01

Read the object graph

Classic xref tables and PDF 1.5 xref/object streams, resolved through a cached Document facade.

02

Inflate the streams

A from-scratch zlib/DEFLATE decoder that borrows straight out of the source bytes — no allocation per Huffman code.

03

Decode the fonts

ToUnicode CMaps, standard encodings, and /Differences collapse into one byte → text mapping per font, parsed once and cached document-wide.

04

Interpret the content stream

A streaming tokenizer feeds a text-state machine that tracks positions, sizes, and image paint points — pages run in parallel.

05

Recover the structure

Heuristics turn positioned glyph runs into headings, list items, and reflowed paragraphs; image sentinels become Markdown links.

Honest limits

What it will not do

A converter that claims everything works is lying. These are the known edges.

Tables, multi-column figure captions, and complex math layout come out as best-effort reflowed text.

Fonts with no ToUnicode CMap, no standard encoding, and no /Differences array will silently drop glyphs.

The heuristics target academic and prose documents. Forms and invoices will not reconstruct well.

Encrypted PDFs and LZWDecode streams are unsupported by design — they return a clean error.
